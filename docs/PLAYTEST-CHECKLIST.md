# Owner playtest checklist

Use this after delivery on your own desktop. No group study or recruitment is required. Engineering tests and automated keyboard completion establish working mechanics; they do not establish uncoached human comprehension, enjoyment or broad accessibility. Those claims remain untested until you try the experience.

Before starting, export personal work, confirm the actual AI provider/model is configured, and reset the demo. Use a comfortable browser zoom and keyboard/mouse. Stop or change settings whenever needed. Record only useful observations; no account or external reporting is required.

- [ ] **Discover play:** without consulting the route guide, move, vary jump height, collect the first star and identify the three-star goal. Note any unclear control or decorative object that looked interactive.
- [ ] **Pause and resume:** pause in a recognizable position, make no edit, resume and confirm the same position/camera. Try typing A/D/E/Space in the AI form and confirm gameplay does not respond.
- [ ] **Safe behavior edit:** select Pip, request float 0.8 and inspect the real change/impact. Resume from the preserved moment and reach the high flower ledge. If the proposal is classified differently, follow its actual message rather than assuming it is safe.
- [ ] **Checked terrain edit:** undo that AI edit and confirm Pip float is 0. Select optional float ledge under Platforms & ledges, use From authored spawn, and Check this jump. Understand “no route found” as a bounded search result, not proof of impossibility. Ask Make this ledge reachable; inspect the real proposal, route witness and restart explanation before Apply. Play the new route with the unchanged character.
- [ ] **Discover the teaching encounter:** pick up Tossable sprout near Practice puff, throw it and bounce toward Lantern terrace. Note whether the visual cues explain the interaction.
- [ ] **Use the mechanical tool:** select the optional ledge and choose Preview a checked step. Confirm its no-AI label, review the ghost/diff, Discard once, then preview/Apply/Undo. Compare the route with the AI-assisted version.
- [ ] **Make a rule directly:** make a plant throwable, configure Mossling's thrown-hit transformation and bounce 900, then pick up/throw with E and bounce to the side perch. Compare your expected outcome with what happened.
- [ ] **Light and recovery:** enable an enemy’s light-fear behavior, then carry the lantern toward it. Take damage, activate a checkpoint, restart there and compare star/health state with Restart level.
- [ ] **Keep control:** undo and redo one complete AI transaction. Make a manual adjustment and ask the model to report the current value without changing it. Confirm no redundant mutation. Lock an object and confirm the action layer rejects AI modification.
- [ ] **Durability:** export, reload and import the project. Confirm authored object positions and properties remain correct and runtime collection did not delete authored stars/enemies. Importing an invalid file should leave the world unchanged.
- [ ] **Finish the starter:** reset and complete the original three-star route without float, then inspect the victory choices. Use the longer route hints in DEMO.md only after a first attempt if needed.
- [ ] **Comfort:** try your usual display/zoom, sound mute and reduced-motion setting. Note clipped controls, hidden scroll affordances or text that is hard to read. Mobile layout is usable for inspection but does not include touch gameplay controls.

Optional notes: record the build, browser/viewport, goal, expected outcome, observed outcome and whether the issue repeated. If you time a task, keep raw elapsed time and visible AI/provider wait separately; an outage is a system issue, not a play-skill failure. Do not replace a failed live request with a fixture and call it successful AI.
